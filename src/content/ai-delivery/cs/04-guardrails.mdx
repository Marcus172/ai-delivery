### Nejdřív skripty, štíhlý kontext

Tokeny se neutrácejí za to, co zvládne skript. Deterministické kroky flow, třeba určení cílových release linií, příprava pracoviště, běh brány nebo slučování stavu, jsou skripty: agent je zavolá a&nbsp;dostane zpátky krátký výsledek, místo aby četl soubory a&nbsp;dopočítával si to sám. Kontext agenta zůstává pro to, co vyžaduje úsudek.

Co se do kontextu dostane, prošlo dietou kontextu. Skilly, pravidla i&nbsp;instrukce říkají na řádek nebo dva, co dělat, a&nbsp;pro zdůvodnění odkazují do dokumentace; většina pravidel se načte, jen když agent sáhne na soubor, kterého se týkají. Instrukce žijí v&nbsp;jednom souboru nezávislém na vendorovi, který čte každý agentní nástroj.

### Regresní testy pro AI setup

Prompty a&nbsp;pravidla jsou kód, takže mají testy. Sada sond spouští čerstvé headless sessions, položí otázku a&nbsp;odpověď ověří regulárním výrazem; zároveň měří tokenovou baseline čerstvé session. Jedna anonymizovaná sonda: *„Přidal jsem import z&nbsp;jiného balíku v&nbsp;monorepu. Co mám spustit před commitem?“* Odpověď musí jmenovat opravu závislostí a&nbsp;instalaci. Spuštění sady je po každé změně setupu povinné.

Sada má vlastní metodiku. Sonda na pravidlo vázané na cestu musí jmenovat soubor v&nbsp;jeho rozsahu, jinak je z&nbsp;principu nestabilní. Opakování pokrývá jen chyby infrastruktury, nikdy špatnou odpověď. Rozptyl modelu se zapisuje jako rozsah úspěšnosti, ne jako nejlepší los.

### Kontextová vrstva, měřená dvakrát

Místo grepování repozitáře se agent ptá generovaného manifestu balíků a&nbsp;lokálního code grafu (CodeGraph; telemetrie vypnutá, nic neopouští stroj) přes tenký wrapper a&nbsp;průzkum dělá subagent jen pro čtení. Přínos se měří, nepředpokládá: experiment s&nbsp;baseline, akceptačními kritérii a&nbsp;opakovanými běhy. Dotazy jsou rychlé; drahé je číst jejich výstup, a&nbsp;proto je výstup zhuštěný do krátkého shrnutí. Ukázaná jsou jen zlepšení, která vydržela opakovaná kola, a&nbsp;ta dvě, která vydržela, jsou oddělená, takže jsou i&nbsp;ukázaná odděleně.

### Deterministické brány, každá z&nbsp;incidentu

Co umí zkontrolovat stroj, není v&nbsp;promptu, ale v&nbsp;bráně. Každý krok lokálního zrcadla CI brány má v&nbsp;hlavičce incident, kterému brání: kontrola schématu mocku, protože kvůli jednomu chybějícímu poli zůstaly obrazovky v&nbsp;mock režimu měsíce prázdné; kontrola chyb dotazů, protože upgrade klientské knihovny vyprázdnil desítky obrazovek; kontrola, že texty přístupnosti zůstávají v&nbsp;jednom namespace, protože se rozlezly do šestnácti. Kde existuje starý dluh, brána používá postupné zpřísňování: dluhový soubor se smí jen zmenšovat, takže nové chyby blokuje a&nbsp;staré se splácejí.
