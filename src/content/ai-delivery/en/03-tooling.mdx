  <Fact k="Why">Parallel agents moved the bottleneck from tokens to RAM and CPU: end-to-end tests, the monorepo's build and type-check, long-running research agents.</Fact>

### Operations, not tools

<Facts label="Operations, not tools">
  <Fact k="Seven operations">Where am I, who is online, create a workspace, run a command there, deliver a brief to an agent, what is running, archive.</Fact>
  <Fact k="Two axes">Where the working copy is created and where the brief lands stay apart. A tool that covers both hands itself an opaque handle, and every tool name stays out of the generic layer.</Fact>
  <Fact k="A swap changes">Files of the personal layer only: the fleet provider, the checkout provider, the workspace UI, the preferences.</Fact>
  <Fact k="A swap leaves">The git state replica, the dotfiles profile, ssh, the worktree hooks, the orchestration loop, the plan app, the private network.</Fact>
  <Fact k="My choice">Paseo: free, an end-to-end relay, a command line for everything, a daemon as a service, a mobile app. Parallel work on many tickets uses the token budget to the full, which is why it spans the fleet.</Fact>
</Facts>

### The fleet in the contract

Two more extension points, not a tool. Without them the flow behaves exactly as on one machine.

<Facts label="The fleet in the contract">
  <Fact k="Fleet provider">Who is online; create a workspace on a given machine; run a command there.</Fact>
  <Fact k="State store">Where the state of the work lives.</Fact>
  <Fact k="Target machine">Every step that starts work takes one, so a ticket started on the laptop can run on the desktop.</Fact>
</Facts>

A few rules came from failures, not from design:

<Facts label="Rules that came from failures">
  <Fact k="Offline machine">A stop. Taking work over to another machine is an explicit choice, never a silent move.</Fact>
  <Fact k="No duplicate work">Before a workspace is created, three sources are checked in order: the state store, the tool's own registry, and the branch, pushed the moment the workspace exists.</Fact>
  <Fact k="Remote shell">An emergency tool, not the transport. Workspaces, agents and briefs go through the tool's control plane; files and commands go over ssh with checksums and exit codes, because the tool's keystroke delivery proved unreliable.</Fact>
</Facts>

### State of the work: a git replica and ledgers

One git repository, replicated to every machine, holds everything the flow knows about the work.

<Facts label="State of the work">
  <Fact k="Contents">Ticket metadata, the machine-checkable criteria that prove red before green, memory, decision maps, research notes.</Fact>
  <Fact k="Metadata">One JSON file per ticket. A custom merge driver merges it key by key, so an orchestrator on one machine and an agent on the other can both write. Only the same field with two values stops the merge: the same work is running twice.</Fact>
  <Fact k="Ledgers">What the orchestration loop has already done, so it never repeats itself: pull requests reviewed at which commit, fixes checked against every newer release line, tickets the morning briefing has shown. Each machine writes only its own file and the loop reads the union, so ledgers never conflict.</Fact>
</Facts>

### Configuration: a chezmoi profile

<Facts label="Configuration">
  <Fact k="Contents">The shell setup, the personal layer of the flow, agent settings, hooks and personal skills, the services that keep the daemons running, and the secrets, encrypted with age.</Fact>
  <Fact k="Pull-based">Every machine applies the profile from git; no machine is the one where configuration is written.</Fact>
  <Fact k="A new machine">Joins through a guided setup skill. A doctor runs about twenty checks per machine (versions, ssh in both directions, ports, keychain, profile, plugins), each failing line with the exact step that fixes it.</Fact>
</Facts>

### When memory runs short

<Facts label="When memory runs short">
  <Fact k="Before">Under the default service settings, running out of memory once stopped the whole agent daemon with every agent in it.</Fact>
  <Fact k="Now">The service keeps running under memory pressure. A governor pauses the youngest batch job (a test run, a type-check, never an agent session) until memory frees up.</Fact>
  <Fact k="Retries">A wrapper repeats a job only when it died of memory, never when a test really failed.</Fact>
</Facts>
