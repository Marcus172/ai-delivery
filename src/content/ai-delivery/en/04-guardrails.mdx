### Scripts first, a lean context

Tokens are not spent on what a script can do. The deterministic steps of the flow, such as resolving the target release lines, provisioning a workspace, running the gate or merging the state, are scripts: the agent calls them and gets a short result back instead of reading files and working it out itself. The agent's context is left for what needs judgement.

What does go into the context went through a context diet. Skills, rules and instructions say what to do in a line or two and point to the docs for the why; most rules load only when the agent touches a file they apply to. The instructions live in one vendor-neutral file that every agent tool reads.

### Regression tests for the agent setup

Prompts and rules are code, so they get tests. A probe suite starts fresh headless sessions, asks a question and checks the answer with a regular expression, while measuring the token baseline of a fresh session. One anonymised probe: *"I added an import from another package in the monorepo. What do I run before committing?"* The answer must name the dependency fix and the install. Running the suite is mandatory after every change to the setup.

The suite has its own methodology. A probe for a path-scoped rule must name a file inside that scope, or it is flaky by design. Retries cover infrastructure errors only, never a wrong answer. Model variance is recorded as a range of passes, not as the best draw.

### A context layer, measured twice

Instead of grepping the repository, the agent queries a generated package manifest and a local code graph (CodeGraph; telemetry off, nothing leaves the machine) through a thin wrapper, and a read-only subagent does the exploring. Its value is measured, not assumed: an experiment with a baseline, acceptance criteria and repeated runs. The queries are fast; reading their output is what costs, so the output is shaped into a short summary. Only gains that held across repeated rounds are shown, and the two that held are separate, so they are shown separately.

### Deterministic gates, each from an incident

Whatever a machine can check is not in a prompt; it is in the gate. Every step of the local mirror of the CI gate names in its header the incident it prevents: a mock-schema check, because one missing field once left screens in mock mode blank for months; a query-error check, because a client-library upgrade once blanked dozens of screens; a check that accessibility strings stay in one namespace, because they had leaked into sixteen. Where old debt exists, the gate applies gradual tightening: a debt file may only shrink, so new mistakes are blocked while old ones are paid down.
