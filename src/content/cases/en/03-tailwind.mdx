## Why: the styling library was end of life

The whole product was styled with a CSS-in-JS library whose version had reached end of life, while the rest of the stack had moved on to React 19 and the current Next.js. It worked, but by accident rather than by support, and every month on it added risk. Instead of keeping it alive, the team invested straight into the target.

<Glance locale={locale} label="Four reasons to move">
  <Point locale={locale} title="End of life">
    The version in use gets no fixes at all, and it runs outside the supported matrix of the framework it renders in.
  </Point>
  <Point locale={locale} title="Security">
    No security patches. The day a vulnerability or a framework update breaks it, there is no fix to take, only an emergency migration.
  </Point>
  <Point locale={locale} title="Performance">
    Styles are generated and injected at runtime for every new prop combination, with a style registry on every server render. Tailwind compiles them ahead of time.
  </Point>
  <Point locale={locale} title="A blocked stack">
    Its type package held the React types at 18 while the runtime was on 19: bumping the types alone produced 21,656 errors across 52 packages.
  </Point>
</Glance>

## The harness before the first component

Rewriting the styling of a whole product is the kind of work that AI makes cheap and that a team rightly fears, because a hundred small visual regressions are invisible to every existing test. So the first phase converted nothing. It built a harness for [**VRT, Visual Regression Testing**](https://storybook.js.org/docs/writing-tests/visual-testing): every story rendered before and after a change and compared pixel by pixel. It closed the story coverage so that every component had a story next to it, and only then did the conversion start: primitives, shared UI, the domains, removal of the old libraries.

<Stat id="vrt-flake" locale={locale} />

<Detail locale={locale} label="The harness in detail">

The design tokens are the single source of truth. The Tailwind theme is generated from the token constants, about 250 custom properties with dark-theme overrides, and a drift check fails when the generated file and the generator disagree. A verify step compiles probe classes through Tailwind itself and checks every token in both themes; negative probes prove that stock Tailwind colours, sizes and breakpoints do not resolve, so no call site can bypass the tokens. Tailwind's spacing scale was replaced, not extended, by the design system's own steps, so a spacing class means exactly what the old prop meant; without that, every diff would have been one pixel off everywhere.

Base and change may differ only in component and story code: the harness copies its own configuration onto the base, because a config difference once produced 250 false diffs. The run accounts for every expected screenshot against the build's own story index, so a story lost on the base side fails the run instead of showing up as a silent "added". The comparator has its own self-test, thirteen checks on synthesised images in about a second, inside the lint gate.

<Facts label="Markers that keep the harness honest">
  <Fact k="Expected diff">A commit trailer declares an intended visual change and its reason; a declaration that matches nothing fails the run, and it travels with the commit to other release lines.</Fact>
  <Fact k="Audited story">A marker in the story records that a person has actually read its screenshot.</Fact>
  <Fact k="Allowlist">Reserved for stories that are non-deterministic by nature, each with a reason.</Fact>
  <Fact k="Exit codes">Clean, visual change, harness failure, cells lost on the base, invalid trailer: the job fails or warns accordingly.</Fact>
</Facts>

</Detail>

## Primitives: the same props, classes underneath

The biggest surface was never rewritten by hand. The layout and text primitives kept their public prop API byte for byte, but now resolve those props to Tailwind classes: enumerable values to real utilities from a generated safelist, open-ended values through a CSS custom property. The quirks of the old prop library were reproduced on purpose, from responsive arrays to "the last prop wins", because the goal was the same pixels, not a nicer API.

<Stat id="primitive-call-sites" locale={locale} />

<Detail locale={locale} label="Running both systems side by side">

Tailwind and the old library ran in the same codebase for the whole migration, and the app was shippable after every merge. Tailwind's reset stayed off, so it could not rewrite the existing global styles. The utilities sit in a cascade layer and the old rules did not, so the old rule always won: converting a component meant deleting its old definition, never stacking classes on top of it. Tailwind's automatic source detection resolved differently in the two build pipelines and computed spacing as zero in one of them, so the sources are declared explicitly.

</Detail>

  <Point locale={locale} title="Agents">
    Convert the stages, several in parallel on disjoint directories; write the missing stories; chase root causes in the harness.
  </Point>

    Generate and verify the theme and the safelist, count the old call sites per stage, account for every screenshot, run the codemods.

The plan itself was written for agents: one folder with the status table, the recipe of a stage and the list of known traps, read by every agent next to its instructions. When an agent proposed auditing every screenshot in bulk before merging, a person replaced it with a cheaper rule that holds: read a story before you convert it.

## The gates were green, the truth was in the pixels

The harness had a blind spot, and it taught the most useful lesson of the migration. Every story of the charting library was a screenshot of an empty chart, taken at the first frame of its animation, and every gate was green, because the base and the change were equally empty. It was found by a person reading the screenshots. A fix to the harness is invisible to the harness, because both sides change together; only eyes see it.

Other defects passed every automated gate as well. Each one became a rule or a test:

<Facts label="Defects that passed the gates, and the rule each became">
  <Fact k="Empty charts">A canvas paint changes neither layout nor DOM, so the settle rule fired at the first frame. Chart animations are now off in the harness.</Fact>
  <Fact k="Lost focus ring">An arbitrary variant was emitted after the focus-visible ring and removed it. Rule: measure the order against the compiler for each variant.</Fact>
  <Fact k="Lost hover">Deleting a wrapper handed its hover rule to a converted child that emits its own. Rule: re-check specificity for every descendant selector.</Fact>
  <Fact k="Dark theme only">Seven dialogs lost their focused fill in dark mode, a header border disappeared. Rule: every state needs its dark twin.</Fact>
  <Fact k="Invalid CSS">Old styles such as a cursor set to false had never applied; a valid equivalent would have widened controls. Rule: check every branch of a conditional style.</Fact>
  <Fact k="Erased labels">An old global reset outside any layer wiped every utility on labels, 1,248 changed screenshots with all other gates green. It moved into the base layer.</Fact>
  <Fact k="Finished or not started">A table filled its rows after first paint and was shot empty on whichever side the race landed. Timer and mutation probes now decide, and a fixture story holds it.</Fact>
</Facts>

<Note>
  <strong>Harness over conversion.</strong> When the settle rule turned out not to distinguish "stable because finished" from "stable because not started", fixing the harness outranked converting the next component. The re-estimate after the pilot moved the cost from the component to its consumers, and the plan was rewritten around that instead of defended.
</Note>

## What stays after the migration

<Glance locale={locale} label="The end state">
  <Point locale={locale} title="The old libraries are gone">
    Both libraries, their types, the server-side style registry and the build plugin across 54 configuration files.
  </Point>
  <Point locale={locale} title="The harness stays">
    It runs on every pull request on every release line, and an intended visual change has to be declared.
  </Point>
  <Point locale={locale} title="A rule for what comes next">
    Tokens only, complete class strings, no raw colours or pixels, and no CSS-in-JS coming back, written into the rules every agent reads.
  </Point>
</Glance>

## Why this was not possible without AI

1. **Volume with fidelity.** About 1,300 components in forty stages, converted to the same pixels, while the call sites of the primitives did not change at all.
2. **Coverage before conversion.** The missing stories were written by parallel agents over disjoint parts of the product, so every component had a screenshot before anyone touched it.
3. **A harness worth trusting.** Root causes of flakes and false diffs were chased down one by one until five hundred comparisons in a row came out stable.
4. **People decide.** Reading screenshots, signing off intended changes and setting the scope stayed with people; the agents did the rewriting.
