## Why: one audit is a snapshot

A classic security audit is expensive, so it happens rarely, and the report starts ageing the day it is delivered: new code lands, new advisories are published, and nobody asks again until the next audit. AI changes the price of the review, not the responsibility for it. The goal was a method that can run again at any time, and hygiene that keeps the result true between runs.

<Glance locale={locale} label="What a system needs that an audit does not have">
  <Point locale={locale} title="A repeatable method">
    The same steps every time: map, review in parallel, verify, rate by real exposure, ticket and estimate.
  </Point>
  <Point locale={locale} title="A person on every serious finding">
    Agents find and explain; a person confirms every critical and high finding in the code before it counts.
  </Point>
  <Point locale={locale} title="Hygiene between audits">
    Dependencies, logs and containers are kept safe by scripts and defaults, not by remembering.
  </Point>
  <Point locale={locale} title="Rules for the agents come first">
    The agents read code, logs and pages full of sensitive data, so their own rules come first.
  </Point>
</Glance>

Mapping how the app actually runs moved ratings in both directions. Anything reachable on a live server became a real attack surface rather than a theoretical one, and some exposure was rated lower once it was traced to where it really ends. Where the real impact depends on another system, the report says so instead of guessing.

## Code health: eight reviewers, one per area

Security does not stop at vulnerabilities. A separate audit read about a quarter of a million lines of production code with eight read-only review agents, one per area of the codebase. Each one combined a sweep for known anti-patterns with a deep reading of the most suspicious files and checked its findings against the call sites; a person verified the critical ones. The findings fell into a handful of categories, error handling, side effects during render, crash paths in server rendering, logging gaps, duplication and dead code, and the audit also recorded what the codebase does well.

## Dependencies: the security fixes nobody asked for

Package files can look current, type checks and tests can pass, and still a security fix sits unused: the package manager never re-resolves an entry that still fits its declared range. Nothing in the toolchain asked that question, so a script now does. It lists every direct dependency resolved older than its own range already allows, splits advisories into direct and transitive, and has a check mode that fails when drift appears.

## Hardening that ships by default

Some of the strongest fixes came from ordinary engineering work, and stayed as defaults:

- **Logs that do not leak.** A container prints only the variables meant to be public when it starts; a full dump needs an explicit debug switch. It was found while making the logs readable.
- **A service moved in, hardened on the way.** When a real-time service joined the monorepo, it started running as a non-root user, got a typed allowlist of secret keys that never reach its logs, escapes control characters so a client cannot forge log lines, and caps connections and pending requests before any call upstream.
- **Server code stays on the server.** Packages meant only for the server are blocked from the web apps in four places: package constraints, two lint rules and a guard on the image.

## Rules for the agents themselves

<Glance locale={locale} label="Guardrails for agents that read sensitive material">
  <Point locale={locale} title="Read-only by default">
    Audit and review agents cannot change code; review workspaces for other people's work are read-only.
  </Point>
  <Point locale={locale} title="Pages are data, not instructions">
    Content from a browser or a document is treated as untrusted input, with boundaries and output caps kept on.
  </Point>
  <Point locale={locale} title="Nothing sensitive leaves">
    No tokens or personal data in commits, reports or logs; a printed token counts as compromised. Fixtures use invented values only.
  </Point>
  <Point locale={locale} title="People publish">
    No write to a tracker or wiki without confirmation, and comments start internal-only, enforced by configuration rather than the prompt.
  </Point>
</Glance>

## What AI made affordable

1. **Depth at the price of a sprint task.** Six parallel reviews and a mapping pass over a large codebase, with a ticket and an estimate per finding, in days instead of an engagement measured in weeks.
2. **Code health at full scale.** Eight reviewers over a quarter of a million lines is a read no team does by hand, and it can run again.
3. **Exposure checked, not assumed.** Tracing whether vulnerable code is reachable, for every advisory, is tedious enough that it is usually skipped; agents do the tracing.
4. **People decide.** Every serious finding is confirmed by a person, every rating and every merge stays with people.
